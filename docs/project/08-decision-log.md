| D-026 | **Isolated PDF Extraction.** Text-layer PDFs are an AI source, read by an isolated extractor and never inside the Nuxt process. (1) A text-layer PDF is an AI-readable source in AI Document Source V1 (`aiReadableNow = true` in the shared format contract). (2) The original PDF is never sent to an AI provider or to any external PDF, OCR or file service; only bounded extracted text reaches the one provider the administrator selected. (3) PDFs are read by `document-extractor`, a security-isolation sidecar container whose only job is untrusted PDF bytes in, bounded text or one fixed failure code out. (4) The sidecar has no database, Directus, AI-provider or product access; it receives no project secret and no environment file, mounts no volume and keeps nothing: the PDF is written only to its tmpfs `/tmp` under a name the service generates, and deleted when the task ends. It sits on an internal Docker network with no route out. Docker publishes no port for a container that is only on an internal network, so a gateway container built from the same image publishes `127.0.0.1:8787` and forwards each connection, unread, to the one fixed address `document-extractor:8787`; the gateway parses nothing. (5) The parser is Poppler — `pdfinfo` for the page count and encryption, `pdftotext -layout` for the text — run as child processes with an argument array, never through a shell, with no retry and no fallback parser. (6) Isolation has two hard layers: every Poppler process runs under an OS address-space limit (`prlimit --as`, 384 MB, no core dump), and the container is capped at 512 MB of memory with no extra swap, 1 CPU and 64 processes, with a read-only root filesystem, every Linux capability dropped, no-new-privileges and a non-root user. (7) V1 limits: 20 MB per PDF (checked in Nuxt against trusted file metadata and again while streaming the download, and checked again by the sidecar itself), 50 pages, 20,000 characters of text, and one 15-second deadline for the whole task — queue wait, `pdfinfo` and `pdftotext` together — enforced by killing the process. One PDF is parsed at a time, at most three wait, and a further request is told `busy`. (8) A PDF over 50 pages is refused (`too_many_pages`), never silently cut to its first pages, because a later page may hold a value that contradicts an earlier one. (9) A scanned PDF with no text layer returns `no_text`: V1 performs no OCR and no vision. A password-protected PDF, and in V1 any encrypted PDF, returns `encrypted`. (10) A PDF's text returns to the unified `ExtractedSource` and the one existing Proposal Engine: the same content dedupe, fingerprint, character caps, reading budget (`MAX_TOTAL_EXTRACTION_MS`), product model relevance guard (D-025) and single provider call as every other source. (11) D-022 continues to apply: this is a narrow exception for one security-isolation sidecar and its port gateway only, and authorises no general microservice architecture, AI platform, business service or file-conversion platform. (12) Production deployment, and a production runtime capacity check of RAM and CPU, remain separately authorised steps; this decision deploys nothing. | Confirmed |
| D-027 | **Bounded XLSX Extraction.** Standard .xlsx workbooks are an AI source, read inside the Nuxt process by a bounded streaming reader and never loaded whole. (1) A standard `.xlsx` workbook is an AI-readable source in AI Document Source V1. (2) `.xlsx` is accepted by the Media Library upload route and is AI-readable (`mediaUploadSupported = true`, `aiReadableNow = true` in the shared format contract); an upload must match both the official MIME type and the extension. An archive may hold at most 1,000 entries. An unsafe entry name (absolute, drive-letter, `..`, backslash, NUL, or one that becomes any of these under NFKC) and a part name that appears twice are refused as `malformed`, so no parser differential can choose between copies. A DOCTYPE, DTD or entity declaration in any part is refused as `malformed`, so no entity is ever expanded; XML depth is capped at 128 and any single XML token at 1 MB. Only the parts the workbook needs are opened — never external links, embedded objects, drawings, charts, media, custom XML or macros. (8) Only visible sheets are read. Hidden and very hidden sheets, hidden rows and hidden columns — including zero-height rows, zero-width columns and values hidden by a `;;;` number format — never reach AI. (9) A formula contributes only the value Excel last saved for it. Formulas are never recalculated; formula text, external workbook paths and external links are never output; a formula with no cached value, or with an error value, is empty. (10) The extracted text keeps the workbook's structure: `Sheet:` for each visible sheet, `Columns:` for its first non-empty visible row (an empty header cell is named by its column letter), and one line per data row with cells separated by ` | ` (a `|` inside a value is escaped). A merged cell's value is looked up from the merge's anchor, never inherited from the row above; empty rows and fully empty columns are left out. Numbers are written without floating-point noise, and only explicit percentages, a number followed by one simple quoted unit, and unambiguous date and time formats (1900 and 1904 date systems) are interpreted; any other value is written as stored and no Excel formatting engine is reproduced. (11) When the current product has a non-empty `product_code` containing at least one letter and one digit, a sheet may be narrowed deterministically. A sheet that does not name the code is kept whole — a single-model workbook often has no model column. (12) Model matching is exact only: no edit distance, prefix, suffix, substring, similar-model, filename, folder-name or AI-call matching. `LT180` is not `LT180C`, and `LT180C-S` is not `LT180C`. The deadline is enforced by the application: the reader runs in-process with no OS-level memory limit, and its safety rests on bounded input, counted inflation, streaming XML, these counters and the single-parse gate. (16) No database schema, Directus schema or collection is added; workbooks stay in the Media Library and are linked to products through `products_files`. (18) Extracted workbook text exists only for the lifetime of one analysis and is never persisted, cached or logged. | D-028 | **XLSX Semantic Fidelity Correction.** A workbook's text shows each number as Excel shows it, and exact product-code narrowing of a column-oriented sheet keeps the columns that describe each row. This corrects D-027 (10) and (11) on these two points only; the rest of D-027 stands. (1) A number stored under a V1-supported simple number format is written with the decimals that format shows, never with the hidden precision it is stored with. The supported formats are a plain number — `0`, `0.0`, `0.00`, `0.000`, the same with a thousands separator (`#,##0`, `#,##0.0`, `#,##0.00`), and the built-in formats 1–4 and 37–40 — a percentage (`0%`, `0.0%`, `0.00%`, built-in 9 and 10), and a plain number followed by one simple quoted unit (`0" mm"`, `0.0" kW"`, `0.00" kg"`, `#,##0.0" bar"`). A `0` decimal place is always written and a `#` decimal place only when its digit is not a trailing zero; at most 30 decimal places are read, and a longer run is written as the stored number. So 0.45 under `0.0` is `0.5`, 0.45 under `0.00` is `0.45`, 0.456 under `0.00" kW"` is `0.46 kW`, 180 under `0" mm"` is `180 mm`, -0.45 under `0.0` is `-0.5`, and 0.456 under `0.00%` is `45.60%`. (2) Rounding is ordinary decimal rounding, half away from zero, applied to the 15 significant digits Excel keeps and never to the binary value, so 0.35 under `0.0` is `0.4` and 1.005 under `0.00` is `1.01`, as Excel shows them. It only follows the precision the format displays: it never adds precision and never recalculates a value. No thousands separator is written and the decimal mark is always `.`, because both marks come from the reader's locale rather than from the workbook; the sign of a negative number is always written. (3) A formula still contributes only the value Excel last saved for it and is never recalculated; a cached number follows the same supported formatting. (4) Dates and times (1900 and 1904 date systems), a value hidden by a `;;;` format, and the stored-number fallback for every other format — currency, scientific, fractions, conditions, several meaningful sections, elapsed time, padding and locale-specific codes — are unchanged; no Excel formatting engine is reproduced. (5) When a sheet is narrowed as column-oriented (D-027 (11)), every visible column to the left of the first column whose header names the exact product code is kept as descriptor context — the parameter, unit or range that describes each row — together with every column whose header names the exact code, for the data rows with a value under that code. Descriptor columns are chosen by position, never by interpreting what a header says, and a column with no value in the header or in the kept rows is left out. (6) To the right of the first matched column, only a column whose header names the exact code is kept: another model's column, and a column between model columns such as a note, are left out. Because the rule reads position rather than meaning, a column to the left of the first match is kept whatever its header says, including another model's column, which keeps its own header; attribution stays with the D-025 guard. (7) Hidden columns, including zero-width columns, remain excluded wherever they are. (8) The row-oriented rule, exact-only matching (no fuzzy, edit-distance, prefix, suffix, substring, filename, folder-name or AI-call matching), the rule that only a code with both a letter and a digit narrows a sheet, the `Filtered to exact product code:` line, keeping a sheet whole when it does not name the code, and the D-025 Product Model Attribution Guard are unchanged. (9) No source format, dependency, database or Directus schema, collection, provider adapter, provider behavior or provider call is added; `ExtractedSource`, the shared prompt contract and the one analysis path are unchanged. | Confirmed |

(11) V1 limits: 20 MB per image (checked against trusted file metadata, while streaming the download, and by the sidecar); at most 12,000 px wide, 12,000 px high and 50,000,000 pixels, checked from the header before any pixel is decoded (`too_complex`); the raster is scaled down, never up, to a longer edge of at most 3,000 px; one 20-second deadline for the whole task — queue wait, header, preparation and OCR — or less when the analysis reading budget (`MAX_TOTAL_EXTRACTION_MS`) has less left. (12) EXIF metadata is used only to turn the image upright; the prepared raster carries no metadata, and no GPS, camera, author, software, comment, XMP or IPTC data is ever returned. A transparent image is flattened onto white; an image without alpha is not flattened. (13) At most 3 images belong to one analysis, within the 5-source limit; the server counts them from the files' stored types before anything is downloaded and refuses a larger selection with a fixed message and no provider call; AI Source Intake stops a fourth image from being selected. (15) The normalized transcription of one image is at most 8,000 characters; a longer one is `too_complex`, never cut. Each image source's text starts with `OCR transcription — low-confidence text is marked [?].` and claims nothing about accuracy. (16) One deterministic pass in page-segmentation mode 3 keeps Tesseract's lines; a word with confidence below 40 is written as `[?]` rather than the guessed characters, neighbouring uncertain words share one `[?]`, a line of nothing but `[?]` is left out, and a transcription with no confident letter or digit is `no_text`. The confidence value is a transcription-reliability signal, not a measure of truth.
